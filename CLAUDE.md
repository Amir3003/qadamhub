# QADAM Project Instructions & Hard Rules

## Tech Stack
- Frontend: React 19, TypeScript, Vite, Tailwind CSS, React Router v7.
- State: React Context + localStorage.

## Strict Engineering Rules (Never Break)
1. **README FILTER:** `README.md` may be edited whenever it is out of date (owner's permission, 31 October 2026), but it is public-facing, so filter every line. Never put in tokens, API or service keys, webhook URLs, passwords, real `.env` values, private emails or phone numbers, personal paths, internal links to strategy, pricing or competitor documents, or anything that was ever leaked. Environment variables appear by name only, with a placeholder or a description, never a value. Keep the install and run steps correct (commands from `package.json`, the real repository name, `.env.example`), state which variables are public and which are server only, and keep the "secrets and security" section. Re-read the diff for secrets before every commit.
2. **NO AI CLICHÉS / FORMATTING ERRORS:** 
   - Never use em dashes (`—`).
   - Never use emojis (`🚀`, `✨`, etc.) in UI code or documentation.
   - Keep design clean, modern, and professional (no toxic neon glows, no pure black `#000` backgrounds).
3. **BUILD INTEGRITY:** Every code change must compile cleanly. Always verify with `npm run verify` to ensure 0 TypeScript errors.

## Agentic Workflow and Hard Constraints
Compiler and build output come first; written rules come second.
- **No blind coding:** before changing any component, read the related files and types. Never guess an API, a prop or a function signature.
- **Self-healing loop:** no task is done until `npm run verify` (`tsc --noEmit`, then `tsc && vite build`) has run after the last file change and exited 0. If it fails, read the trace, fix the code, and run it again until it passes. Never report "done" without that run.
- **Browser check for UI:** any UI change also needs a real headless browser run: add or update a scenario in `tests/smoke/ui-smoke.spec.ts` that opens the changed screen and clicks the new element, run `npm run test:ui` (Playwright, desktop and mobile; fails on a blank page, `pageerror` or `console.error`; in a cloud session set `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium`), then open the screenshots in `/tmp/ui-check` with Read (after a deploy, `npm run test:live` checks the production site with the real feed; Supabase is answered in the browser, nothing touches the database) and look at spacing, text overflow, z-index and modal scrolling. Report which screenshots were checked.
- **Architecture limits:** never silence checks with `any`, `@ts-ignore`, `@ts-expect-error` or `eslint-disable`, and never loosen `tsconfig.json` (`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch` stay on). Never break global scrolling (no `overflow-hidden` or `h-screen` on root layouts). Add no npm package unless there is no reasonable alternative.
- **Text and UI style:** no emojis, no em dashes, no filler. In academic and AI contexts say "AI & Machine Learning", not "Computer Science".
- **Commands:** `/plan <task>` (read-only plan), `/ship <task>` (implement, loop on verify, browser check for UI), `/audit` (review the git diff and fix). Files in `.claude/commands/`.

## Core UI/UX Requirements
- **Global Page Scrolling:** Ensure natural browser-level scrolling (`html, body, #root { overflow-y: auto; height: auto; }`). Never trap viewports in fixed `h-screen overflow-hidden` containers that break scrolling.
- **Modals & Dropdowns:** Target benchmark selectors and modals must use proper positioning (`z-50`, bounded height with `overflow-y-auto`) so they never get obstructed or cut off. Modals (quizzes, forms, wizards, dialogs) close only through their visible close button (or Cancel in a confirm dialog): no backdrop click and no Escape, so progress is never lost by accident. Dropdowns and menus may still close on an outside click.
- **Mobile Layout:** Maintain proper bottom padding (`pb-28`) on all main views so content is never obscured by the fixed mobile navigation bar.
